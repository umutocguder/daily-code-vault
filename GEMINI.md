# Workspace Guidelines: Development & Continuous Git Sync

## 1. Safety & Confidentiality Boundaries (STRICT RULE)
- **Company / Work Code**: NEVER automatically commit, push, or sync any company, work-related, proprietary, client, or employer code/data to GitHub or any remote repository.
- **Personal Scope**: Auto-commit and auto-push apply strictly to your personal repositories and coding vaults.

## 2. Frequent Commits & Continuous Git Sync
- Whenever we write code, implement features, or make progress on personal projects:
  - Commit and push frequently to GitHub (`origin main`).
  - Use clean Conventional Commit messages (`feat:`, `fix:`, `refactor:`, `docs:`, `test:`).
  - The background auto-sync watcher runs continuously to ensure every unit of work is backed up and synced in real-time.

## 3. High-Velocity & Quality Development
- Develop actively and flexibly without unnecessary restrictions.
- Write clean, modular, and maintainable code with tests and docstrings where appropriate.
